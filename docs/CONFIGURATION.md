# 配置导出与恢复

在“设置与数据 → 配置迁移”点击“导出配置（含密钥）”，浏览器下载 `MyLab-settings-v1-日期.json`。之后在同一处点击“一键导入配置”，选择该文件即可应用，无需逐项粘贴。升级通常不会清除已保存的普通设置；密钥原本只在页面内存，刷新后需重新填写或导入。必须在关闭或刷新前导出，网页无法找回已丢失的密钥。

当前配置包含模型地址、模型名称、个人 API Key、本机服务地址及配对码、GPU 系统地址、X 来源与配色、主题和检查间隔。旧版翻译提示词、X Token、公众号 RSS 等字段保留导入兼容，但新界面不再使用；X 自动根据账号生成 FxTwitter 地址，翻译固定为“翻译为中文。”。JSON 是明文文件，请自行妥善保存；网页不会把它上传到 GitHub。导出命名已加入 `.gitignore`。导入后密钥仍只在页面内存，不写入 localStorage 或普通数据备份；导入本身不调用模型或测试接口。

配置文件不包含任务、文章内容、周报和 GPU 申请记录，这些内容继续通过“导出备份”保存。GPU 登录会话、登录弹窗中临时输入的账号密码、浏览器通知权限、本机 `.env.local` 的代理等服务配置不属于网页设置。配对码可以恢复，但本机服务重启后旧码失效，需使用终端显示的新码。

导入会覆盖文件中明确提供的配置项，空字符串也会恢复；旧文件缺少的项目保留当前值，在新设备上使用当前默认值。订阅按稳定 ID 合并，已有文章引用保持有效，文件中没有的订阅仍保留；订阅刷新状态重新检查。验证失败时不修改任何配置，也不显示包含密钥的原始解析错误。只导入自己保管的文件。

## 后续版本的兼容约定

- 格式标识固定为 `format: "mylab-settings"`，当前 `schemaVersion: 1`。格式版本独立于应用版本；增加可选配置不应直接递增格式版本。
- 兼容入口集中在 `src/config-transfer.ts`。新增 `Settings` 字段必须补充默认值与对应校验器；新增 `Secrets` 字段必须补充密钥长度规则，两者都有 TypeScript 完整性约束。它们会自动进入导出字段表。
- 字段重命名、结构改变时，增加从旧格式到当前格式的显式迁移，再执行校验；不要删除旧读取路径。遇到高于当前支持的格式版本，应提示升级，不能猜测后静默覆盖。
- 保留 `tests/fixtures/settings-v1.json` 作为不可随实现重写的历史兼容样本。其中只有虚构测试凭据。后续发布继续运行此样本和往返、缺字段、内容保留、错误保护测试；现有 GitHub Actions 已运行完整测试。
- 同版本额外未知字段忽略；不执行配置文件中的指令，不通过文件引入自动接口请求。新增来源字段须同步导出、导入校验和历史样本测试。
