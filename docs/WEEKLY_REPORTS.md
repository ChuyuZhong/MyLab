# 个人科研周报

入口：[写周报](https://chuyuzhong.github.io/MyLab/#/weekly)。所有个人材料和草稿保存在当前浏览器，GitHub Pages 仅提供页面和通用写作规则。

## 写作习惯如何归纳

梳理了 77 份 Markdown 周报的全文、结构和论文条目，重点细读近期连续十周的记录，并抽读早期代表记录。对应的 PDF 作为格式和文件命名的交叉核对，重复导出不重复计数；统计表不作为写作样本。原文件保留在用户本机，公开规则没有附带历史项目、实验数据或周报片段。

全文保留“学习内容 → 项目进展 → 下周计划 → idea小记”。论文占主要篇幅，其余部分简短。

论文先列原题和已知出版信息，以加粗的研究任务起句，再用自然段说明：任务和输入输出、数据如何构建、方法中真正发生了什么、贡献属于数据还是机制、评测是否支持结论、自己的疑问与可借鉴点。篇幅通常约 250–500 字；材料充分且紧密相关时可以更详细。不能凭公众号标题推测论文原题、录用状态、实验指标或自己尚未做过的工作。

项目进展简述实际动作、当前状态和问题；下周计划按行动顺序列出；idea 保留开放问题和待验证方向。整理掉偶发错字与重复编号，保留直接、带判断的研究笔记语气。

完整规则是 [chuyu-weekly-report/SKILL.md](../public/skills/chuyu-weekly-report/SKILL.md)，网页构建直接读取同一份文件。把整个 `chuyu-weekly-report` 目录放入个人 Codex skills 目录即可复用，也可以将 SKILL.md 作为其他写作工具的规则。调用示例：`使用 $chuyu-weekly-report，根据这些阅读笔记和本周事项整理周报。`

## 使用流程

1. 在公众号阅读页打开文章，点击“加入本周周报”；或者在周报页按已读、收藏、全部、已选筛选材料。每份最多 12 篇，依次按加入顺序整理。
2. 展开“补充理解”，填写已知的论文原题、期刊年份团队及阅读笔记。公众号目录通常只有链接，可在文章页“补充正文”，或在阅读笔记里粘贴关键节选并注明来源。
3. 选择周内任一天，页面自动归到周一至周日。任务按实际完成时间归周，按本机时区计算；本周到期但未完成的 DDL 不会进入完成清单。新草稿默认选中该周已有的完成 DDL，后续新增的完成项可以用“选中本周全部”补入。
4. 补充其他工作、下周计划、idea 和可选的其他学习内容。署名可以留空，每行一件事即可。
5. 点击“本地整理”，将已有笔记原样放入相应栏目；或在设置填写个人模型接口后，点击“按我的写法生成”。模型只接收本页明确选中的材料与输入，使用完整写作规则。DDL 清单由页面确定性组装，保留任务名、截止时间和实际完成日期。
6. 核对预览，切换“编辑 Markdown”修改，然后下载。也可以点击“复制 Markdown”在本地编辑器中保存，或从空白稿直接撰写。草稿按周自动保存，切周或刷新后可以继续；备份导出和合并导入包含周报。

材料变化后，旧稿继续保留并提示尚未更新。重新整理或生成会替换当前稿件，可先下载保留重要修改；它不是版本历史管理器。模型响应不完整或请求取消时保留旧稿，切周或离开页面会取消正在进行的请求。

## 材料和接口边界

- 已读标记代表阅读记录，不等于已取得论文全文。只有链接且无笔记的条目明确列为待阅读；节选和个人笔记会保留材料范围说明。
- “补充正文”中的内容来自用户，页面不保证已核对论文原文。模型整理后仍需复核事实、判断及出版状态。
- 所选材料最多 60,000 字符，超出后提示减少篇数或缩短正文，不静默截断。请求使用非流式 Chat Completions，输出上限设置为 8,192 tokens，超时 90 秒。模型需能按提示返回 JSON 章节；格式不符会保留原稿并提示重试。
- 与助手、翻译共用 Base URL、模型名和内存中的 API Key。密钥不写入仓库、localStorage 或备份，刷新后需重新填写。调用会把所选内容发送给用户配置的模型服务。
- Markdown 预览支持标题、列表、表格、链接与代码，不执行内嵌 HTML，也不自动加载文章中的外部图片。
- 原始周报、私人调试资料和模型测试配置未纳入公开仓库。开发站与正式站的数据按网站来源隔离。
